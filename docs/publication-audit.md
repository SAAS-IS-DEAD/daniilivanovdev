# Аудит перед публичной публикацией

Дата: 2026-11-08. Область проверки: исходники, добавляемые файлы и Git-история
всех локальных и полученных remote refs. GitHub сейчас имеет видимость PRIVATE;
изменение видимости не является частью этого коммита.

## Результат проверки секретов

- Gitleaks 8.30.1: совпадений с секретами не найдено в истории и снимке файлов,
  допустимых к коммиту. Бинарник скачан из официального release; SHA-256 архива
  проверена. Использованы стандартные правила, без baseline/allowlist и без
  доверия к inline `gitleaks:allow`; вывод сканера полностью редактируется.
- Первый проход охватил 19 коммитов. Дополнительная проверка 287 Git blob objects
  не нашла приватных ключей и PostgreSQL URL с непустым паролем, отличным от
  тестового значения, шаблона или подстановки переменной.
- Package lock содержит ссылки на публичный registry.npmjs.org.
- `.env` и `.deploy-secrets/` существуют локально и не входят в Git. Это данные
  доступа, а не мусор: они сохранены и исключены также из Docker-контекста.

Это проверка на известные форматы секретов и дополнительный просмотр метаданных,
а не математическое доказательство отсутствия любых возможных чувствительных
данных. Серверные Secrets, содержимое GHCR-образов и все старые Actions logs
не входят в этот аудит репозитория.

## Персональные и операционные данные

Репозиторий не обезличен:

- `apps/api/src/cli/resume-data.ts` содержит реальные имя, телефон, email и
  данные резюме. Контакты используются публичным сайтом и намеренно сохранены,
  чтобы не менять содержимое портфолио без отдельного решения владельца.
- Прямые ссылки на исходное резюме hh.ru удалены из текущих spec/plan/validation.
  Они остаются в старых коммитах; изменение файла не очищает историю.
- Git-история содержит имена/email авторов, включая email, отличный от контакта
  портфолио. Старые документы содержат сведения о деплое и локальных путях.

**Вывод:** признаков утечки рабочих ключей/токенов в Git не обнаружено. Открывать
репозиторий можно только с учётом того, что перечисленные персональные данные
и прежние ссылки станут доступны читателям истории. Для полностью обезличенной
публикации сначала потребуются замена данных и согласованная очистка истории;
force-push или изменение опубликованной истории автоматически не выполнялись.

## Что предотвращает повторное попадание файлов

- Git и Docker исключают локальные PDF/отчёты, временные директории, env-файлы,
  каталоги секретов, npm credentials, kubeconfig и распространённые файлы ключей.
- Созданные по запросу PDF и результаты нагрузочных тестов сохранены локально,
  но не добавляются в исходники или image build context.
- Удалены найденные `.DS_Store` и Python bytecode cache файлы.
- `test:ci` проверяет ignore-политику, отсутствие защищённых файлов в индексе
  и обязательность secret scan перед публикацией Docker-образа.
- CI сканирует полную Git-историю Gitleaks; image publication зависит от этого
  job наравне с остальными обязательными проверками.

## Валидация

Новые защитные проверки сначала упали по ожидаемым причинам: временные/секретные
пути не были исключены, secret-scan job отсутствовал. После изменений прошли
`npm run verify` (включая отдельную Testcontainers PostgreSQL, coverage и 6 CI
checks) и 11 Playwright E2E на свежей Docker-сборке с отдельными PostgreSQL/Redis.
Тестовые контейнеры и volume удалены; рабочая БД не использовалась для fixtures.

Дополнительно прошёл `npm run test:load:integration`: настоящий k6 отклоняет
пустую отдельную PostgreSQL и успешно читает профиль через Nest/GraphQL.
