# Feature Specification: Цифровая визитка с синхронизацией hh.ru

**Branch**: `001-digital-business-card` · **Updated**: 2026-11-04
**Status**: публичная визитка реализована; синхронизация спроектирована, доступ к источнику не подтверждён.

По указанию владельца авторизация сайта, админка и публичный CRUD отменены.
Прежние US3/US4, FR-004–009/011, SC-002/003 в редакции с админкой больше не действуют.
История требований сохранена в `archive/before-hh-sync/`; это не активный backlog.

## User Scenarios & Testing

### US1 — Проверяющий получает профиль (P1)

Apollo Sandbox и публичные GraphQL queries возвращают профиль, навыки, опыт и проекты.
Поля выбираются запросом, отсутствующие связи возвращаются пустыми списками;
служебные данные синхронизации и секреты не публикуются. Публичных mutations нет.

### US2 — Посетитель знакомится со специалистом (P2)

Публичный React-сайт показывает данные API, loading/error/retry/empty,
работает на 360/1440 px, с клавиатурой и touch. Интерактивный проводник и арканоид
сохраняются; существующие подробные требования приведены ниже.

### US5 — Проверяющий воспроизводит запуск (P1)

Docker подготавливает схему и начальные данные. Чистый запуск не зависит от hh.ru.
Повторный seed и restart сохраняют импортированные данные и не создают дубликатов.

### US6 — Владелец обновляет визитку через резюме (P2)

Владелец редактирует своё резюме на hh.ru; воркер обновляет визитку без админки.

1. При полном валидном ответе обновляются только поля, назначенные источнику hh.ru.
2. Повторная обработка того же содержимого не создаёт новых записей и не меняет их ID.
3. При 403/404/429, таймауте, капче, неполной странице или неверных данных остаётся
   последняя успешная версия; ошибка фиксируется без содержимого резюме и секретов.
4. Локальные проекты, контакты/ссылки и визуальные ресурсы не удаляются синхронизацией.
5. Два воркера не применяют обновление одновременно. Ошибка посреди записи откатывает
   всю транзакцию. Посетитель видит целостную версию профиля.
6. Запуск синхронизации доступен оператору через CLI; публичного HTTP/GraphQL запуска нет.

## Functional Requirements

- FR-001–003: сохранить публичный профиль, Sandbox и сайт.
- FR-010: импорт проходит серверную валидацию существующих ограничений контента;
  недопустимые значения не обрезаются молча и не записываются частично.
- FR-012–014: результат успешного импорта виден при следующем чтении, seed идемпотентен,
  README объясняет запуск, архитектуру, источник и известные ограничения.
- FR-015: доступность клавиатуры, текстовых состояний и reduced motion сохраняется.
- FR-016: отдельный воркер запускает синхронизацию при старте и раз в 24 часа;
  это начальное принятое значение, настраиваемое оператором.
- FR-017: при недоступности источника сайт работает с последним успешным снимком.
- FR-018: синхронизация идемпотентна, атомарна и не затрагивает локальные поля.
- FR-019: запуск без настроенного доступа к hh.ru поддерживается; синхронизация
  по умолчанию выключена до подтверждения рабочего источника.

## Success Criteria

- SC-001: пример GraphQL из README возвращает профиль и связи через Sandbox.
- SC-002: валидный снимок применяется целиком; повторный импорт не создаёт дубликатов.
- SC-003: ошибки загрузки/разбора/записи и параллельный запуск не повреждают профиль.
- SC-004: чистый Docker-запуск без доступа к hh.ru показывает seeded профиль.
- SC-005: публичный интерфейс доступен на 360/1440 px без горизонтальной прокрутки.
- SC-006: результаты проверок фиксируются отдельно; работающий live-sync не заявляется
  без успешного чтения реального источника и повторного прогона.

## Дополнение владельца: интерактивный интерфейс (2026-11-04)

Публичный frontend получает тёмную тему и оригинального пиксельного персонажа из
Downloads владельца. Персонаж приветствует посетителя и предлагает маршруты к опыту,
проектам, навыкам и контактам. Наведение или клавиатурный фокус на месте работы дают
краткий рассказ; нажатие открывает полное описание. На touch-устройствах всё доступно
касанием. Предусмотрены reduced motion, ручная пауза и корректное управление фокусом.
Содержимое резюме остаётся в API; изменяется представление и навигация.

### Дополнение: мини-игра навыков (2026-11-04)

По запросу пользователя раздел навыков содержит арканоид: ракетка управляется
мышью или удерживаемым пальцем, столкновение шарика с блоком навыка убирает
блок с поля. Реальные навыки профиля не изменяются. Предусмотрены клавиатурное
управление и запуск кликом/касанием самого поля без отдельных кнопок управления.
Уход мыши из поля ставит игру на паузу; на телефоне пауза при отпускании пальца.
Полный список навыков с поиском всегда виден ниже игры, без переключателей.
Сохраняется приглушённая зелёная/графитовая палитра.

## Обязательное тестирование — 2026-11-05

По указанию владельца каждая фича должна иметь unit-тесты поведения, а backend-фича
дополнительно интеграционные Nest/HTTP/GraphQL + отдельная PostgreSQL. Это критерий
готовности, а не отложенная задача. Багфикс сопровождается регрессионным тестом.
`npm run verify` обязателен; см. AGENTS.md и docs/testing.md.
