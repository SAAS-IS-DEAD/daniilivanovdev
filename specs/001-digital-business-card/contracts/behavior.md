# Поведение интерфейсов

schema.graphql — проектный целевой контракт, не готовая реализация сервера.

## HTTP и GraphQL

- GET /graphql с Accept: text/html — embedded Apollo Sandbox, явно включённый в production.
- POST /graphql application/json — операции. GET queries допустимы по правилам Apollo CSRF;
  GET mutations запрещены. Интроспекция доступна. HTTP batching отключён.
- Все queries контента публичные; отсутствие объекта → null, списка → []. me без
  действующего входа → null. Чтение не меняет контент и не продлевает сеанс.
- Все mutations, кроме login, требуют активной сессии. Все mutations требуют
  X-App-Request: web и разрешённый Origin, если Origin присутствует. Аутентифицированные
  mutations дополнительно требуют X-CSRF-Token, совпадающий с токеном сеанса.
- login возвращает Viewer и Set-Cookie. me позволяет восстановить состояние UI и CSRF-токен
  после обновления страницы. На me/login и любые аутентифицированные ответы — Cache-Control: no-store.
- Cookie production: __Host-session, Secure, HttpOnly, SameSite=Lax, Path=/, Max-Age=86400;
  локальная HTTP-cookie session-dev с теми же свойствами кроме Secure и имени.
- CORS: только APP_ORIGIN, credentials=true, заголовки Content-Type, X-App-Request,
  X-CSRF-Token, Apollo-Require-Preflight. Другие Origin не получают доступ с credentials.
  Ошибки Origin/CSRF — HTTP 403 до изменения данных. Non-browser CLI без Origin разрешён
  только с нужными заголовками и сессией; он не обходит авторизацию.
- Sandbox проверяет публичные запросы. Не разрешать сторонний Origin для защищённых операций
  ради Sandbox. При нестандартном поведении embedded UI исправлять размещение/настройку клиента,
  не отключать CSRF и не открывать CORS всем.

## Лимиты запросов и introspection

Контентные queries и mutations: depth <= 6, expanded fields <= 50.
Отдельная pure-introspection query получает depth <= 20 и expanded fields <= 2000,
не более трёх корневых field occurrences. После раскрытия fragments её корневые поля
могут быть только __schema, __type и __typename; имена проверяются по AST field.name,
не по alias или operationName. Наличие любого другого корневого поля, включая me,
переводит всю операцию под обычные лимиты 6/50: исключение не переносится на контент.
Глубина корневого поля равна 1. Каждое вхождение поля, включая aliases, __typename
и повторно использованный fragment, считается отдельно; @skip/@include не уменьшают
стоимость. Проверка циклов fragments выполняется до раскрытия, обход прекращается
сразу после превышения бюджета. Не выбранные operationName операции не исполняются;
каждая потенциально исполняемая операция проверяется по той же политике.
Общий предел тела и текста GraphQL-документа — 64 KiB, batching запрещён в обоих режимах.
Превышение AST-лимита возвращает BAD_USER_INPUT до выполнения resolvers.
Проверки включают реальный introspection-запрос встроенного Sandbox, aliases/fragments,
смешанную query с profile/me и превышение каждого лимита. Изменение этих значений
потребует явного обновления контракта, а не отключения защиты при запуске.

## Определение IP за прокси

CLIENT_IP_MODE=direct (локально по умолчанию): Express trust proxy=false;
ключ лимита берётся только из socket.remoteAddress. Forwarded, X-Forwarded-For,
X-Real-IP не влияют на него; Vite proxy в dev считается одним источником.
CLIENT_IP_MODE=trusted-proxy: TRUSTED_PROXY_CIDRS содержит явный список доверенных
IP/CIDR реального ingress; пустой/невалидный список и 0.0.0.0/0 или ::/0 запрещены.
Express trust proxy использует только этот список, не true и не число hops.
Адрес вычисляется справа налево: socket peer → X-Forwarded-For; первый недоверенный
адрес считается источником. Если socket peer не доверен, весь заголовок игнорируется.
IPv4-mapped IPv6 приводится к IPv4 перед HMAC; отсутствующий/некорректный адрес или
некорректная доверенная цепочка отклоняет login с BAD_USER_INPUT, без смены ключа на email.

Для Render выбирается trusted-proxy: до включения production-входа оператор фиксирует
проверенный список ingress IP/CIDR и источник этих сведений в docs/deployment.md,
проверяет отсутствие обходного публичного пути к контейнеру и поведение X-Forwarded-For.
Список нельзя подменять всеми private ranges или угадывать по одному запросу.
Проверки на реальном сервисе: запросы из двух известных источников определяются раздельно,
подставленный левый X-Forwarded-For не меняет вычисленный источник, а прямой запрос
от недоверенного peer не получает доверия к заголовкам. Проверка проводится закрытым
диагностическим средством без публичного debug endpoint и публикации клиентских адресов.
Если провайдер не позволяет подтвердить доверенную цепочку, production-вход не выпускается:
нужен контролируемый ingress/другая площадка с тем же контрактом. Локальная работа продолжается.

## Ошибки

GraphQL errors[].extensions.code: BAD_USER_INPUT, UNAUTHENTICATED, FORBIDDEN,
NOT_FOUND, CONFLICT, RATE_LIMITED, INTERNAL_SERVER_ERROR. Валидация добавляет
extensions.fields: [{path, message}]; лимит — retryAfterSeconds. Внутренние сообщения
Prisma и stacktrace не отправляются. Непредвиденная ошибка логируется с requestId без тела
запроса, cookie, пароля и токенов; клиент получает requestId и общее сообщение.
Ошибки исполнения GraphQL могут приходить с HTTP 200: клиент проверяет errors всегда.
Невалидный транспорт/синтаксис может возвращать 400, неправильный метод — 405.
Ошибки отдельного mutation не откатывают другие mutations в том же документе;
клиент отправляет одну изменяющую операцию за раз, атомарность — внутри операции.
Повторная отправка create после потерянного ответа может создать дубль проекта/опыта:
автоматических повторов mutations нет, UI предлагает перечитать список.

## Маршруты UI

| Маршрут | Доступ и поведение |
|---|---|
| / | Публичный профиль, разделы и ссылки; загрузка, ошибка с повтором, пустые состояния |
| /admin/login | Форма email/password; общее сообщение об ошибке, ожидание при лимите |
| /admin | Вход обязателен; форма профиля, links как упорядоченный список |
| /admin/skills | Список и формы навыков |
| /admin/experience | Список и формы опыта |
| /admin/projects | Список и формы проектов |

Защита маршрута обеспечивает UX; реальная проверка доступа выполняется сервером.
После mutations список перечитывается; после выхода память клиента очищается.
Frontend вызывает методы SDK, сгенерированные GraphQL Code Generator для graphql-request.
Единый transport в client.ts задаёт credentials и текущие CSRF-заголовки при каждом вызове,
обрабатывает ClientError без логирования variables. SDK не заменяет серверную проверку доступа.
Формы доступны с клавиатуры; фокус виден, ошибки связаны с полями, удаление подтверждается.
Ссылка открывается с noopener/noreferrer; контент не передаётся в dangerouslySetInnerHTML.
При истечении доступа UI сообщает об этом, не отправляет отложенную mutation автоматически
после нового входа. Пароли и формы не сохраняются в localStorage.

## Health и операционные команды

GET /health/live — 200, если процесс отвечает. GET /health/ready — 200 при соединении
с БД, иначе 503; оба не раскрывают конфигурацию. Эти endpoints не заменяют GraphQL API.
Команды admin:create и admin:reset-password доступны только оператору локально/в контейнере;
пароль не передаётся аргументом shell и не печатается. Reset отзывает все сеансы.
